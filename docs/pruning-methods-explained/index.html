APoZ — Average Percentage of Zeros

Prune filters that are "sleeping" — zero most of the time after ReLU
Pipeline
1
Hook ReLUs
Register forward hooks on the ReLU after every Conv2d. We measure post-ReLU activations.
→
2
Count Zeros
For each filter, count how many activations = 0 across all images and all spatial positions (B × H × W).
→
3
Compute Score
APoZ = zeros / total
Score in [0, 1]. Higher = more dead.
→
4
Prune
Per layer: sort by APoZ descending. Remove the top ratio fraction (highest APoZ = most dead).
Example: 8 filters in one conv layer, 50% pruning ratio
← Keep (low APoZ)
Prune (high APoZ) →

What it measures: The fraction of a filter's post-ReLU activations that are exactly zero. A filter at 0.95 APoZ is "sleeping" 95% of the time — it almost never responds to any input at any spatial position.

What it misses: A filter that always outputs the exact same positive value (say 0.8 for every image, every pixel) has 0% zeros — APoZ sees it as perfectly healthy. But it's actually uninformative because it never varies. Entropy catches this case.

Our cutoff adaptation: The original paper uses a mean-plus-one-standard-deviation cutoff on the per-layer APoZ distribution (which removes ~16% of filters under a Gaussian assumption). We replace this with a direct percentile cutoff so that exactly the target fraction r is removed, keeping the protocol comparable across methods.

In our code (apoz.py)
# Hook post-ReLU outputs:
zeros_ch = (act == 0).float().sum(dim=(0, 2, 3)) # per-channel
apoz = zeros / total # Eq. 1 from Hu et al.

DropNet — Expected Activation Magnitude

Prune filters with the weakest average post-ReLU response
Pipeline
1
Hook ReLUs
Same as APoZ — hook the ReLU after each Conv2d to capture post-activation outputs.
→
2
Spatial Average
For each filter, compute mean(|act|) across H×W spatial positions per image.
→
3
Average Score
Average across all calibration images. score = mean over all images. Continuous, not binary.
→
4
Prune
Per layer: remove the lowest-scoring filters — weakest average activation.
Example: 8 filters scored by average activation magnitude
Prune (low magnitude) ←
→ Keep (high magnitude)

What it measures: How strongly a filter responds on average — a continuous "activation energy" signal. Where APoZ asks "is it zero or not?" (binary), DropNet asks "how strongly does it fire?" (continuous). A filter that outputs 0.01 consistently would score very low even though APoZ might see it as active.

Key difference from APoZ: DropNet uses per-layer ranking rather than a global threshold, because activation scales differ massively across VGG-16 layers. Early layers process large spatial maps with small values; deep layers produce small maps with large values.

Our adaptation — one-shot, not iterative

The original DropNet paper prescribes an iterative prune-then-fine-tune schedule: a small fraction of filters is removed, the network is retrained, and the process is repeated. Under the benchmark protocol, DropNet is collapsed to one-shot: scores are computed once on the pretrained baseline, the target fraction is removed in a single step, and all fine-tuning is deferred to the shared 10-epoch post-pruning step. This isolates DropNet's scoring criterion from the recovery boost its iterative loop would otherwise contribute, so it is compared on the same terms as every other method.

In our code (dropnet.py)
gap = act.abs().mean(dim=(2, 3)) # (B, C) — spatial average of |activation|
score[c] = (1/N) * sum(gap[:, c]) # average over all images

Why? A single feature map has 224×224 = 50,176 values. We can't directly measure the "variation" of 50,176 numbers across thousands of images — that's millions of data points per filter. GAP compresses each feature map down to one number: the average activation across all spatial positions. This gives us one clean scalar per image that summarises "how strongly did this filter respond overall to this image?" Now we can ask: does that summary number change between different images, or does it stay the same?

Why a histogram? Shannon entropy is defined over a probability distribution — it needs probabilities, not raw numbers. But we have a list of continuous-valued scalars (like 0.44, 0.67, 0.12…), not discrete events. The histogram converts these continuous values into a discrete distribution: divide the range into 256 equally-spaced buckets, count how many values fall into each bucket, and divide by the total count. Now each bucket has a probability pi, and we can apply the entropy formula.

Why 256 bins? The paper doesn't specify an exact number. 256 is a standard default — enough granularity to distinguish genuinely different response patterns, but not so many bins that most are empty (which would make the estimate noisy). With ~10,000 calibration images, 256 bins gives roughly 40 samples per bin on average, which is enough for a stable estimate. Using 64 or 512 would work too — the ranking between filters is robust to the exact bin count.

Step 4 — Shannon Entropy: quantifying spread
H = −Σ pi · log(pi)
Sum over all non-empty bins

The formula simply measures how spread out the probabilities are across the bins. If values are evenly distributed (many bins with similar small probabilities), the log terms produce a large negative sum — high entropy. If almost all probability is concentrated in one or two bins, the sum is small — low entropy.

What entropy catches that APoZ and DropNet miss

Filter B outputs 0.80 for every image. APoZ sees 0% zeros — it thinks the filter is perfectly healthy. DropNet sees a strong average magnitude — it also thinks the filter is important. But it carries zero useful information because it never varies. It's like a smoke detector that always reads "medium" regardless of whether there's smoke or not. Entropy correctly flags it because all 10,000 scalars land in the same histogram bin, giving near-zero entropy.

In our code (entropy.py)
# Step 1: GAP — compress H×W feature map to one scalar per image
gap = output.mean(dim=(2, 3)).cpu() # (B, C) → one value per filter per image
 
# Step 3: Histogram — estimate probability distribution from N scalars
counts, _ = np.histogram(values, bins=256)
probs = counts / counts.sum() # normalise to probabilities
probs = probs[probs > 0] # drop empty bins (0·log0 = 0)
 
# Step 4: Shannon entropy — Eq. 1 from Luo & Wu (2017)
H = -np.sum(probs * np.log(probs)) # high H = informative, low H = prune

HRank — Feature Map Rank

Prune filters that produce spatially repetitive feature maps
Pipeline
1
Collect Maps
For each filter, collect the H×W post-ReLU feature map it produces for each calibration image.
→
2
SVD → Rank
Compute the matrix rank of each H×W map using SVD. This counts linearly independent rows.
→
3
Average
Average the rank across all calibration images. Stable even with small batches (paper Fig. 2).
→
4
Prune
Remove lowest-rank filters — they produce the most spatially repetitive output.
What "rank" means for a feature map
Rank 1 — Repetitive
Every row is a copy → PRUNE
Rank 2 — Moderate
Two distinct patterns
Rank 4 — Rich
Every row unique → KEEP

What it measures: The spatial complexity of a filter's output. A rank-1 feature map means every row is a scaled copy of the same pattern — the filter detects something, but it's saying the same thing everywhere. A high-rank map has diverse structure at different positions.

What it misses: Each filter is judged in isolation. A filter could produce a rich, high-rank feature map, but if three other filters in the same layer produce the exact same map, it's still redundant. HRank wouldn't notice that duplication — CHIP would.

In our code (hrank.py)
# Hook the ReLU *after* each Conv2d (post-ReLU is essential for rank differentiation)
rank = torch.linalg.matrix_rank(fmap_2d.float())
rank_sum[c] += rank # accumulate over images
score[c] = rank_sum[c] / num_images # average rank

→

→
4

What it measures: Whether a filter is telling the layer something new. Unlike HRank (which judges each filter alone), CHIP looks at all filters together and asks: "If I remove this one, can the remaining filters reconstruct what it was saying?" If yes, it's redundant.

Our 8×8 pooling adaptation: At 224×224 input, the first conv produces a 64×50,176 matrix — and a layer of width C requires C+1 SVDs per image (one full + one per masked row), so 65 for layer 1 and up to 513 for the deepest VGG-16 layers (C=512). This is far too slow at 224×224 resolution. We pool to 8×8 first (giving a C×64 matrix), which is ~780× faster and preserves inter-channel relationships. This matches the spatial scale the original paper operated at with 32×32 CIFAR-10.

CHIP vs HRank

HRank can miss a filter that's individually complex but duplicated across the layer. CHIP catches this overlap. Conversely, CHIP can miss a filter that's spatially simplistic but happens to be the only one capturing that signal. They find different kinds of waste.

In our code (chip.py)
pooled = F.adaptive_avg_pool2d(maps, 8) # 224→8 adaptation
A = feature_maps.reshape(C, H*W).float()
original_norm = svdvals(A).sum() # nuclear norm
A_masked[i, :] = 0.0 # zero out channel i
ci[i] = original_norm - svdvals(A_masked).sum() # Eq. 3

LRMF — Learned Representation Median in Frequency Domain

Prune filters that look most similar to their neighbours — in the frequency domain
Pipeline
1
Hook Conv2d — per batch, per image
Hook the raw Conv2d output directly — pre-ReLU. For each batch → for each image in the batch: collect C feature maps of shape H×W (one per filter).
→
2
2D DCT
Transform each feature map into the frequency domain using a 2D Discrete Cosine Transform.
→
3
Low-Freq Crop
Keep only the top-left quarter of the DCT matrix. Flatten it into a compact descriptor per filter.
→
4
Distance Matrix — per image, accumulated
Per image: compute C×C pairwise Euclidean distances between descriptors; add each filter's row-sum to a running total. After all batches: divide by number of batches (not number of images).
→
5
Prune
Lowest row-sum = the "median" filter, most surrounded by similar neighbours → prune.
Pre-ReLU hooking — why LRMF (and HRank) are different

APoZ, DropNet, Entropy, and CHIP all hook the ReLU after each Conv2d — they need post-activation values because their criteria depend on ReLU behaviour (zero-counting, activation magnitude, etc.).

LRMF hooks the Conv2d output directly (before ReLU), matching the original paper's repo which captures output.data from the conv layer. This is because LRMF compares the shape and structure of feature maps via DCT, not their activation statistics. ReLU would clip all negative values to zero, distorting the frequency-domain representation. The raw conv output preserves the full signal — including negative values — which gives a more faithful frequency fingerprint.

So in our codebase, 5 methods hook post-ReLU (APoZ, DropNet, Entropy, HRank, CHIP) and 1 hooks pre-ReLU (LRMF). HRank hooks post-ReLU because ReLU's zeroing of negatives is what makes rank-1 collapse easy to detect; without it the rank would rarely drop low enough to discriminate filters.

Both feature maps contain the same gradient — one is just shifted. In the spatial domain, their pixel values are in completely different positions, so a direct distance comparison says "these are very different." But DCT decomposes the image into frequency components (how much of each wave pattern is present), and shifting an image doesn't change its frequency content — only its phase. Since LRMF compares frequency magnitudes, the two maps become nearly identical. This reveals redundancy that spatial-domain comparisons would completely miss.

Why only the low-frequency quarter?

Top-left = low freq (broad structure)

DCT organises information by frequency. The top-left corner of the DCT matrix holds the low-frequency components — these describe the broad structure of the feature map (overall gradients, large blobs, dominant patterns). The bottom-right holds high-frequency components — fine-grained detail, sharp edges, pixel-level noise.

Most energy lives in the low frequencies. This is a well-known property of natural images (and it's why JPEG compression works). For feature maps, the same applies: the broad structure carries the meaningful signal, while high-frequency detail is mostly noise or spatial jitter that varies between images.

Cropping to ¼ serves two purposes: it removes noise that would make distances between similar filters appear larger than they really are (making redundancy harder to detect), and it dramatically reduces the descriptor size. For a 224×224 feature map, the full DCT has 50,176 values per filter; the cropped quarter has only ceil(224/4)² = 56² = 3,136 values — a compact fingerprint that captures the essence of each filter's output.

Each cell D[i][j] is the Euclidean distance between filter i's DCT descriptor and filter j's. A small distance means those two filters produce similar frequency patterns — they're redundant.

The row-sum is each filter's total distance to all other filters. A filter with a small row-sum sits in the middle of a cluster — it's close to many neighbours who are producing similar things. That's the "representation median."

F2 has small distances to F1, F3, F4, and F5 — it sits in the center of the pack. Its contribution is already well-covered by surrounding filters. F1 is the outlier — far from everything else — meaning it captures something unique that no other filter covers.

This is computed per image; row-sums are summed across all images within each batch, then accumulated across all batches, then divided by the number of batches (not the number of images — matching the original paper's implementation). This means the final score scales with batch size, but relative rankings between filters are preserved regardless.

Our adaptation — one-shot, not iterative soft masking

The original LRMF implementation uses iterative soft masking: the bottom-scoring filter weights are zeroed at regular intervals during training and gradients are masked accordingly, effectively baking a form of fine-tuning into the pruning loop. Under the benchmark protocol, LRMF is applied as a one-shot structural pruning criterion: scores are computed identically to the paper (DCT → low-freq crop → pairwise distance row-sum), but channel removal is performed in a single step and no fine-tuning is applied until the external standardised 10-epoch protocol runs.

In our code (lrmf.py)

# Step 2–3: DCT + low-frequency crop

fd[c] = dct_full[:a, :a].ravel() # a = ceil(side/4), top-left quarter
 
# Step 4: Pairwise distance matrix + row-sum score
dist_mat = cdist(fd, fd, 'euclidean') # C×C matrix (paper Eq. 8)
score = dist_mat.sum(axis=1) # row-sum: low = median = prune

GFS — Greedy Forward Selection LOCAL*

Build a subnetwork by greedily adding the most valuable filters — starting from nothing
Key Insight: Forward Selection ≠ Backward Elimination

Most pruning methods remove filters from a full network (backward elimination). GFS does the opposite: it starts with an empty layer and greedily adds the filter that most reduces the loss. The paper proves that forward selection from a sufficiently over-parameterised pretrained network achieves a prediction error of O(1/n²), while training a same-sized network from random initialisation with standard gradient descent achieves only O(1/n).

Paper pipeline — per-layer ε-stopping (no cross-layer score pool)
1
Empty Layer
Start with set S = ∅. All filters in the layer are candidates. Zero the entire layer's output.
→
2
Try Each — per layer, all images at once
For each candidate: zero all weights in the layer except S ∪ {k}, scale by Nh/|S ∪ {k}|, forward a 64-image mini-batch through the full model (not just this layer), compute cross-entropy at the final classifier. At each greedy step only up to 20 random candidates are tried — not all remaining filters. Data pre-collected once, reused every step.
→
3
Add Best
Pick k* = argmin loss. Add it: S ← S ∪ {k*}. Scale output by Nh/|S| to match magnitude.
→
4
Repeat
Repeat steps 2–3 until |S| = nkeep filters. Earlier selections get higher importance scores.

Why forward selection beats backward elimination
Forward selection (GFS)
Start empty, add best filter each step.
Each step considers the not-yet-selected pool (in our implementation, up to 20 random candidates).

Backward elimination (most other methods)

No similar convergence guarantee.

What it measures: The direct contribution of each filter to the network's actual loss. Unlike heuristic criteria (magnitude, sparsity, rank), GFS uses the real loss function as the scoring criterion. A filter is important if adding it to the subnetwork meaningfully reduces the classification loss on calibration data.

Computational cost: GFS is significantly more expensive than local scoring methods. The paper's worst case is Nh × nkeep forward passes per layer (every remaining candidate evaluated at every step). Our adaptation caps candidates at up to 20 random draws per step, reducing the per-layer cost to O(20 × nkeep) — for a 512-filter layer keeping 358 filters that is ~7,160 forward passes, not ~183,000. Even with this cap, GFS remains the most expensive scoring criterion in the benchmark.

Layer-wise sequential application: The paper's Algorithm 1 prunes layers sequentially from input to output. Each layer's pruning immediately affects the input to subsequent layers, so later layers are scored with the already-pruned earlier layers in place.

GFS vs local scoring methods

Local methods (APoZ, DropNet, Entropy, HRank, CHIP, LRMF) score each filter using a proxy criterion — sparsity, magnitude, rank, independence — hoping it correlates with actual importance. GFS skips the proxy entirely and directly measures loss reduction. The trade-off is time: scoring a 512-filter layer with APoZ takes one forward pass; GFS takes thousands (~20 × nkeep with our candidate cap, still orders of magnitude more than the local methods).

LOCAL* — Benchmark classification

Although the original paper proposes GFS with a cross-layer global budget, our benchmark classifies it as local. The importance scores are ordinal ranks (1 to Cout); dividing by layer width maps every layer to the same uniform distribution, making the effective budget allocation identical to a per-layer uniform protocol. The LOCAL* badge reflects this collapse — see the methodology section of the thesis for the full argument.

Our implementation — LOCAL* (identical scoring, single mode)

Our code runs the same greedy forward-selection pipeline as the paper and uses global budget allocation. There is no separate local variant. The LOCAL* classification reflects our analytical finding that ordinal selection-order ranks divided by layer width produce the same uniform distribution per layer as a per-layer uniform protocol — the effective budget allocation is local even though the code pools scores globally.

NISP — Neuron Importance Score Propagation GLOBAL

Trace every filter's contribution forward to the classifier — prune what the classifier doesn't need
Paper pipeline — GLOBAL (propagated scores, cross-layer budget)
1
Identify FRL
The Final Response Layer is the layer whose outputs feed the 10-way classification head — in VGG-16, the second fully-connected layer (4096 neurons).
→
2
Rank FRL Neurons
Forward all calibration batches through the network; collect FRL activations batch-by-batch (no per-image loop). Score each neuron by variance × mean-|activation| across all collected activations.
→
3
Propagate Backward — all layers, no more data
sk = |W(k+1)|⊤ sk+1 — one matrix multiply per layer back to conv1. Pure weight operations: all layers scored in one backward sweep, no calibration images involved.
→
4
Global Prune
Normalize scores per-layer, rank globally, remove bottom fraction.

Key idea: A filter in an early layer can receive a high score even if its own activations look unremarkable — what matters is whether important neurons later in the network depend on it. Importance is a weighted sum of all downstream neurons' importance, with weights being absolute connection strengths.

Why per-layer normalization matters: FC layers are never pruned in our implementation — only Conv2d filters. But normalization is still needed because backward propagation through many weight matrices accumulates scale: early conv layers end up with systematically higher absolute scores than later ones, simply because importance has been multiplied through more layers. Without normalizing each layer to [0, 1] before global ranking, early layers dominate and later layers are never pruned regardless of their actual importance.

Efficiency: One forward pass for FRL activations + one backward sweep of matrix multiplications. No per-image SVD, no backpropagation, no iterative optimization.

FRL ranker substitution: The paper uses Inf-FS (Roffo et al., 2015) for the initial FRL neuron ranking — a MATLAB-only feature-selection algorithm with no maintained Python equivalent. The authors' own ablation shows the propagation step drives performance, not the choice of initial ranker, so we substitute the simpler variance × mean-|activation| score (shares the same intuition: an FRL neuron is informative when its response varies across inputs and has appreciable magnitude).

ThiNet — Reconstruction-based Pruning LOCAL

If removing a filter doesn't change the next layer's output, it's redundant
Paper pipeline — LOCAL (per-layer sequential, fixed ratio per layer)
1
Sample Data — repeated per layer
The full calibration dataloader is re-iterated separately for each layer pair. For each image, pick 10 random spatial positions at the output of layer i+1; each position adds one row to a regression matrix x̂ (shape: C columns, one per channel of layer i). By the end, one matrix covers all images × 10 rows for this layer — no averaging, raw rows stacked.
→
2
Greedy Selection — per layer, on full matrix
Runs once per layer on the complete accumulated matrix (all images combined). No more data passes — purely matrix operations. Picks the T channels whose removal minimises reconstruction error of layer i+1's output.
→
3
Least-Squares
Rescale surviving channels' weights via least-squares to minimize residual error. Better init for fine-tuning.
→
4
Prune + Fine-tune + Next
Remove channels, fine-tune this layer, propagate to next. Repeat layer-by-layer from early to deep.

Key idea: ThiNet looks at layer i+1 (the next conv) to decide what to prune at layer i. If a channel's removal barely changes the next layer's output, it's redundant. This is a reconstruction-based criterion, not an activation-statistics one.

Greedy + least-squares: The greedy algorithm adds one channel at a time to the "remove" set T, always picking the candidate that increases reconstruction error the least. After selection, a least-squares rescaling adjusts surviving weights — this gives the pruned network a much better starting point for fine-tuning.

Strength: Reconstruction-based selection provides a superior initialization. The authors report pruned VGG-16 can even outperform the unpruned baseline, because removing redundant filters acts as regularization.

Our implementation — LOCAL (same pipeline, no per-layer fine-tuning)

Same per-layer sequential greedy selection and least-squares rescaling as the paper. We omit per-layer fine-tuning — all fine-tuning happens once after all layers are pruned. Local only, no global variant.

Last-conv handling: The reconstruction objective needs a "next conv" to reconstruct, which the last conv lacks. The paper handles this by pruning the last conv at half the rate of other layers — but that would break the uniform per-layer ratio and make FLOPs/parameter counts incomparable across methods in this benchmark. We instead keep the target ratio r uniform and fall back to ℓ₁ weight-magnitude ranking for that single layer.

AOFP — Approximated Oracle Filter Pruning GLOBAL

Measure the damage of removing a filter by looking only one layer ahead
Paper pipeline — GLOBAL (damage scores ranked cross-layer)
1
Base Path — all layers cached in one pass
One full forward pass per batch caches every layer's reference output via hooks (no separate pass per layer). The per-layer ablations in step 2 then reuse these cached references — they run partial forwards from layer i to layer i+1, not full passes through the network.
→
2
Random Ablation — all layers, 20 rounds per batch
Per batch, per layer: 20 rounds — each round zeros a random half of that layer's channels and forwards the whole batch. Damage t = mean over images in the batch of normalised squared error (averaged, not summed). t is added to each ablated channel's running total.
→
3
Damage Score — per filter, all layers
t = ||ref - ablated||² / ||ref||², averaged over images in the batch. Final score per channel = mean t across all rounds and batches it was ablated in. All layers share the same cached reference forward — only the partial (layer i → i+1) forwards are repeated per ablation round.
→
4
Global Prune
Low damage = unimportant. Rank all filters globally across layers, remove bottom fraction — cross-layer budget.

Damage Isolation: Instead of observing the final loss (which requires a full forward pass), AOFP shortens the feedback loop to just one layer ahead. This enables independent, simultaneous scoring across all layers.

Half-ablation sampling: Each round randomly zeros half the channels, matching the paper's Binary Filter Search scheme (Algorithm 1, lines 8-10). The damage t is attributed to all ablated filters. Over many rounds, each filter accumulates a reliable average damage score.

DCP — Discrimination-aware Channel Pruning LOCAL*

Keep filters that truly contribute to discriminative power, not just reconstruction accuracy
Paper pipeline — GLOBAL (stage-wise, interleaved fine-tuning)
1
Attach Aux Classifiers
Attach a small classification head at 2 evenly-spaced intermediate conv layers. Each head: BatchNorm → ReLU → AvgPool(1×1) → Linear(C, 10) — takes a conv layer's feature maps and tries to predict the class label directly. This gives every intermediate layer a discriminative loss signal.
→
2
Fine-tune with Joint Loss
L = Lf + λ·Laux
Lf = cross-entropy at the final classifier. Laux = mean cross-entropy at the aux heads. Forward → backward → SGD weight update. Repeated over many batches/epochs to make intermediate layers more discriminative before scoring.
→
3
Score + Select
Forward a batch → compute L → backward → read ||∂L/∂Wj||F per channel. High gradient = channel is being actively used to reduce loss = important. Select top channels to keep; optimize remaining weights via SGD.
→
4
Prune + Repeat
Remove unchosen channels. Return to step 2 (fine-tune) for the next stage. Repeat for all P+1 stages — budget allocated across stages globally.

Key insight: Reconstruction-based methods (like ThiNet) may keep a channel just because it helps reproduce the original feature maps — even if that channel contributes nothing to the classification decision. DCP's aux heads force intermediate layers to be evaluated on whether they can actually classify, not just whether they preserve activations.

Our implementation — LOCAL* (single-pass, per-layer budget)

Same 2 aux heads as the paper (BatchNorm → ReLU → AvgPool(1×1) → Linear(C, 10)), attached at the same evenly-spaced intermediate conv layers. No fine-tuning step — heads are randomly initialised and used directly for gradient scoring.
→
2
Forward + Backward (no weight update)
All calibration batches: forward → compute L = Lf + λ·Laux → backward → read ||∂L/∂Wj||F per channel → accumulate. No SGD step — gradients are only read, weights never change.
Lf = cross-entropy at the final VGG classifier. Laux = mean cross-entropy across the 2 aux heads.
→

Per-layer: remove channels with lowest mean gradient magnitude. No global variant.

Result highlight (paper): On ILSVRC-12, pruning 30% of ResNet-50 channels actually improves accuracy by 0.39% over baseline — the auxiliary losses act as powerful regularizers.

DCP vs ThiNet

ThiNet minimizes reconstruction error alone — it preserves feature maps but may keep discriminatively useless channels. DCP adds classification-aware losses, directly measuring whether a channel matters for the task. This is why DCP outperforms ThiNet by 0.81% top-1 on ResNet-50 at 50% pruning.

REPrune — Kernel Representative Selection LOCAL*

Channel pruning that emulates kernel pruning — select filters covering the most representative kernels
Paper pipeline — GLOBAL (budget from BN γ, training-integrated)
1
Train with Sparsity Loss
Train with BN scaling factors (γ) penalised by a sparsity loss. The γ magnitudes determine per-layer channel counts — global budget via shared regularisation.
→
2
Cluster Kernels
For each layer: cluster weight kernels (Ward's method). The γ-derived channel count sets the target number of clusters.
→
3
Greedy MCP
Maximum Coverage Problem: greedily select filters that cover the most uncovered clusters. Budget per layer (how many to keep) is set by γ.
→
4
Prune + Resume Training
Remove unchosen channels and continue training. Integrated with the training loop.
Our implementation — LOCAL* (skip paper step 1; add explicit budget step)
1
Cluster Kernels (= paper step 2)
Start here — paper step 1 is skipped entirely. No training, no γ factors. Run Ward's agglomerative clustering directly on the pretrained weight kernels.
→
2
Greedy MCP (= paper step 3)
Maximum Coverage Problem: at each step, pick the unselected filter that covers the most currently uncovered clusters (coverage is recomputed dynamically after each pick, not pre-scored). Selection order → ordinal importance scores (first selected = most unique coverage = most important).
→
3
Global Budget → Prune (replaces paper step 1's γ)
Since we have no γ factors to set per-layer budgets, we apply an explicit global pruning ratio: pool ordinal scores across all layers, remove the bottom fraction. This is the step that substitutes for what γ did implicitly in the paper.
How images feed into the filter score
No images — REPrune is the only method in the benchmark that uses no calibration data.
input: pretrained weight tensors Wl ∈ ℝC_out × C_in × kH × kW
→ cluster kernels (Ward's, on weights) → greedy MCP (on clusters, no data)
→ selection order → importance score  # purely structural, no activation statistics
Consequence: given the same pretrained weights, REPrune produces identical pruning decisions regardless of the dataset. Swap the calibration set entirely — the result doesn't change. The only dataset influence is indirect: the weights were shaped by training on that data.

Key insight: Kernel pruning (removing individual 3×3 slices within a filter) achieves fine granularity but produces sparse models needing special hardware. REPrune gets the effect of kernel pruning through channel pruning: it identifies which kernels are similar via clustering, then selects the filters that collectively cover the most representative kernels.

Why Ward's method: Ward's linkage ensures monotonically increasing merge distances, giving a consistent hierarchy. The linkage cut-off hl is set per-layer based on channel sparsity, ensuring clusters reflect genuine kernel similarity rather than an arbitrary threshold.

Our adaptation: The paper's native framework integrates pruning with training via a concurrent training-pruning paradigm using BN scaling factors (γ) to progressively determine layer-wise sparsity. We adapt REPrune to our one-shot benchmark protocol by performing kernel clustering and MCP filter selection directly on the pretrained model's weight tensors — no calibration data or BN γ factors are needed. This isolates the scoring criterion (kernel clustering + coverage maximisation) from the training pipeline. REPrune is the only method in our benchmark that operates entirely on weight structure rather than activation statistics or loss evaluation.

REPrune vs other channel pruning

Most channel pruning methods select filters based on importance scores (magnitude, activation statistics, loss contribution). REPrune instead asks: which subset of filters best represents the diversity of all kernels in the layer? This coverage-based approach preserves kernel-level diversity that importance-based methods might miss — a filter can have low magnitude but contain a unique kernel pattern that no other filter covers.

LOCAL* — Benchmark classification

Although the original paper frames REPrune as a global method, our benchmark classifies it as local. Here is why:

MCP selection produces an ordering — the 1st chosen filter is most important, the last is least. That ordering is converted to a score by dividing by layer width:

Layer A (4 filters): MCP order F3→F1→F4→F2 → scores 1/4, 2/4, 3/4, 4/4 = 0.25, 0.50, 0.75, 1.00
Layer B (4 filters): MCP order F2→F4→F1→F3 → scores 1/4, 2/4, 3/4, 4/4 = 0.25, 0.50, 0.75, 1.00

Both layers produce the exact same set of normalized scores — regardless of which filters MCP picked or why. Global ranking on these scores always removes the same fraction from every layer. Pruning 50% globally = pruning 50% per layer. The global ranking adds nothing.

How the paper avoids this: the paper never computes ordinal ranks. Instead, the BN γ factors are the scores — continuous, learned values shaped by the actual training signal. A redundant layer ends up with most γs near zero; a critical layer keeps them high. The per-layer budget falls out from how many γs drop below a threshold, so different layers naturally lose different fractions. Our one-shot adaptation loses this because we discard the training loop and replace γ with an ordinal rank, which collapses to uniform.

Shared across all 12 methods

After scoring, every method feeds into the same structural pruning + fine-tuning pipeline. Keep-masks are built per layer, then prune_conv2d_layer() physically removes filtered channels and propagates dimension changes forward through the network. All methods then receive identical fine-tuning: 10 epochs, SGD with cosine annealing at LR 0.001, uniform across all parameters. This ensures the only difference between methods is which filters they chose to remove — not how the network was retrained afterwards.
